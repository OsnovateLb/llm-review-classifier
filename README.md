# Классификация отзывов через LLM API (Задание 2)

Скрипт автоматически отправляет отзывы клиентов в большую языковую модель через API. Для каждого отзыва он получает структурированный ответ в JSON:

- **тональность**: `positive`, `negative` или `neutral`;
- **тема**: одна из 8 категорий («качество товара или услуги», «обслуживание и персонал», «цены», «ожидание и скорость», «чистота и атмосфера», «расположение и доступность», «ассортимент», «другое»);
- **уверенность** от 0 до 1;
- **краткая суть** отзыва одним предложением.

В качестве LLM используется **[OpenRouter](https://openrouter.ai)** с **бесплатной моделью** (суффикс `:free`). Ключ бесплатный, банковская карта не нужна. Скрипт работает с любым OpenAI-совместимым API, провайдер меняется одним параметром `--base-url`.

## Пайплайн

```
 Hugging Face API / CSV ──► классификатор ──► OpenRouter API ──► проверка JSON ──► results/results.json
 (реальные отзывы)          пакеты по 10       (JSON Schema)       (схема, id,
                            отзывов                                повтор при ошибке)
```

1. **Чтение данных.** По умолчанию отзывы загружаются через **внешний REST API** Hugging Face datasets-server из открытого датасета [`d0rj/geo-reviews-dataset-2023`](https://huggingface.co/datasets/d0rj/geo-reviews-dataset-2023). Это около 500 тысяч отзывов об организациях с Яндекс Карт, у каждого есть оценка от 1 до 5. Загруженные отзывы сохраняются в `data/input_reviews.csv`. Можно подать и свой CSV.
2. **Запрос к LLM.** Отзывы отправляются пакетами по 10 в Chat Completions API. Модель задаётся явно или выбирается автоматически: скрипт запрашивает у OpenRouter список бесплатных моделей и выстраивает их по приоритету — сначала проверенные крупные модели, затем модели с поддержкой JSON-схемы. Если модель не справляется с ответом, скрипт **сам переключается на следующую**, а «сырые» ответы записывает в `results/debug_failed_responses.txt`. Ответ запрашивается в формате `response_format: json_schema`. Если модель его не поддерживает, скрипт переходит на `json_object`, затем на обычную инструкцию в промпте. Тексты отзывов передаются как данные, и модель не выполняет инструкции из них.
3. **Разбор и проверка.** Из ответа извлекается JSON, даже если модель обернула его в `` ```json `` или добавила рассуждения `<think>`. Скрипт проверяет, что тональность и тема входят в допустимые значения, а результат есть для каждого id. Если проверка не прошла, модель получает текст ошибки и отвечает повторно (до 3 попыток). На ответы 429 и 5xx, а также при сетевых сбоях (обрыв TLS-соединения, таймаут) скрипт делает паузу и повторяет запрос.
4. **Сохранение.** Итог записывается в `results/results.json`: метаданные запуска (провайдер, модель, источник, время, токены), сводка и разметка по каждому отзыву.

В сводку добавлена простая **проверка качества**: тональность от LLM сравнивается со звёздной оценкой автора (4–5 → positive, 3 → neutral, 1–2 → negative).

## Как получить бесплатный ключ

1. Зайдите на https://openrouter.ai и нажмите **Sign in**. Подойдёт вход через Google, GitHub или по e-mail.
2. Откройте https://openrouter.ai/keys, нажмите **Create API Key** и скопируйте ключ вида `sk-or-v1-...`.
3. Пополнять баланс не нужно. Лимит бесплатных моделей: 20 запросов в минуту и 50 в день. 50 отзывов пакетами по 10 — это 5 запросов.

## Запуск

Нужен только Python 3.10+, внешних библиотек нет.

```powershell
# Windows (PowerShell), в папке проекта
$env:LLM_API_KEY="sk-or-v1-ваш-ключ"
python classify_reviews.py --source hf --limit 50 --offset 1000
```

```bash
# Linux / macOS
export LLM_API_KEY="sk-or-v1-ваш-ключ"
python3 classify_reviews.py --source hf --limit 50 --offset 1000
```

Ключ можно не задавать каждый раз: скопируйте `.env.example` в `.env` и впишите ключ туда (файл `.env` в git не попадает).

Повторно обработать сохранённый входной файл (или свой CSV с колонкой `text`):

```bash
python classify_reviews.py --source csv --csv data/input_reviews.csv --output results/results_rerun.json
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--source` | `hf` | `hf` загружает отзывы через API Hugging Face, `csv` берёт локальный файл |
| `--csv` | `data/input_reviews.csv` | путь к CSV (для `--source csv`) |
| `--text-column` | `text` | колонка с текстом отзыва |
| `--limit` | 50 | сколько отзывов обработать |
| `--offset` | случайное | с какой строки датасета HF начинать |
| `--batch-size` | 10 | отзывов в одном запросе к LLM |
| `--model` / `LLM_MODEL` | авто | id модели, например `nvidia/nemotron-3-super-120b-a12b:free` |
| `--base-url` / `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | любой OpenAI-совместимый API |
| `--output` | `results/results.json` | файл результата |
| `--list-models` | — | показать доступные бесплатные модели в порядке приоритета и выйти |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

26 тестов работают без интернета и ключа:
- поддельный клиент проверяет разбор JSON, в том числе обёрнутого в markdown или `<think>`, валидацию, повторы, переход между форматами ответа, сводку, полный прогон на CSV и автоматическое переключение на другую модель;
- **локальный HTTP-сервер, имитирующий OpenRouter**, проверяет настоящий HTTP-клиент: выбор бесплатной модели, повтор после 429, переход на `json_object` после ответа 400 понятную ошибку при исчерпании дневного лимита и ответ «думающей» модели в поле `reasoning`.
